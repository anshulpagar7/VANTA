The problem

Revenue does not vanish.It leaks.

A payment degrades. A checkout is abandoned. A subscription mandate fails. An invoice goes quietly overdue. None of it is dramatic, and all of it adds up.

The naive instinct is to retry. But retrying a hard decline is wasted; an insufficient-funds failure recovers only after the customer has been paid; an abandoned cart is not a payment problem at all. The same error code can mean several different things.

Razorpay already ships the agents

Agent Studio launched in March 2026 on the Claude Agent SDK, with a Subscription Recovery Agent and a Cart Abandonment Recovery Agent, and published principles for how they behave — merchant scope, review-first mode, a kill switch, no invented discounts, no dark patterns.

Nobody publishes the measurement

Building another agent would rebuild something that exists, less well, in two weeks. What does not exist publicly is how you would prove one recovery policy beats another rather than got a lucky simulation. That is the gap.

The model cannotmanufacture authority.

Only the policy engine holds the token that mints an executable action. The executor accepts nothing else. Enforced by tests, not by a diagram.

# execution/types.py
_POLICY_TOKEN = object()

def _mint(token, **kwargs):
    if token is not _POLICY_TOKEN:
        raise AuthorityError(
            "AuthorizedAction may only be constructed by the policy engine")
    return AuthorizedAction(**kwargs)

The honest limit. This bounds what the model may do, not how well it reasons. A wrong diagnosis cannot exceed its permissions, but it can still spend a permitted retry on a payment that was never recoverable. That cost is measured, not explained away.

A world nobodycould tune against.

Outcome probabilities were authored before any policy existed, then frozen. Policy code is forbidden from importing them, checked at the syntax-tree level on every test run. Events are generated on Razorpay's own error axes — source, step, reason.

Ambiguity is the point

The error slug deliberately does not determine the true cause. Without that, diagnosis would be a lookup and a language model would have nothing to contribute.

# world/params.py — frozen
"payment_failed": {
  ISSUER_SOFT_DECLINE: 0.40,
  INSUFFICIENT_FUNDS:  0.30,
  ISSUER_HARD_DECLINE: 0.20,
  TRANSIENT_GATEWAY:   0.10,

Where the model's edge actually comes from

Arm C, development seeds, by failure reason. The gap over B+ is not spread evenly.

payment_failed — highlighted — is the one error code deliberately built to be ambiguous: the rules map can only guess its true cause at 40% confidence. That single reason accounts for almost all of arm C's advantage over B+. Everywhere the answer was already obvious, the two arms are within a rounding error of each other.

The test that nearly killed this result

The first version declared the model had earned its place whenever its mean beat B+. On development data the gap was ₹24,522 while each arm's own interval exceeded ₹85,000 — by that reading it was indistinguishable from noise, and the report would have been overclaiming.

The correct comparison is the paired per-seed difference, since both arms run on identical seeds. Common random numbers cancel the shared variance, and the paired interval came out at ₹18,918 — narrower than the effect. It survived, then strengthened out of sample.

What thisdoes not prove.

  • The world is synthetic. Outcome probabilities were authored, not observed. Each is marked sourced or assumed, and every assumed value is a sensitivity axis.
  • The same author wrote the world and the agents. The mitigation is structural rather than a promise — policy code cannot import the world — but it is a mitigation, not an elimination.
  • One holdout run. By design. Had the numbers disappointed, they would still be the numbers on this page.
  • Five seeds is a small sample. The paired test is what makes an effect this size detectable at all.
  • Nothing is trained, deliberately. The only data comes from the frozen world, so fitting a model to it would mean learning the answer key.

Unmodelled: churn as a downstream cost of over-contacting, seasonality, issuer policy drift, any correlation between payment size and recoverability. Each would likely narrow the gap between arms, so this spread is an upper bound rather than a forecast.
