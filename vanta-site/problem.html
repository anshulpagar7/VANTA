01 — The problem

Revenue does not vanish. It leaks.

A payment degrades. A checkout is abandoned. A subscription mandate fails. An invoice goes quietly overdue. None of it is dramatic, and all of it adds up.

Recovery is a decision problem, not a retry problem

The naive instinct is to retry. But retrying a hard decline is wasted; retrying an insufficient-funds failure works, though only after the customer has been paid; an abandoned cart is not a payment problem at all and needs a link, not a retry. The same failure code can mean several different things.

So the real question on every at-risk payment is not can we retry but what is most likely wrong, what is the best intervention, when should it happen, and is it worth doing at all. Get that last part wrong and you burn the customer's patience on money you were never going to recover.

Razorpay already builds the agents

Agent Studio launched in March 2026, built on Anthropic's Claude Agent SDK, shipping with a Subscription Recovery Agent and a Cart Abandonment Recovery Agent. They also published their principles for how those agents behave: merchant-defined scope, review-first mode for sensitive actions, a one-tap kill switch, no invented discounts, no dark patterns, permanent suppression on opt-out.

Building another recovery agent would be rebuilding something that already exists, less well, in two weeks.

What is not published — by Razorpay or anyone else — is how you would prove that one such agent is better than another. That is the gap VANTA fills.

Why proving it is genuinely hard

You cannot A/B test a recovery agent against real customers casually: the treatment is money and attention, and the control group is customers you deliberately did not help. So you simulate. And the moment you simulate, you inherit a credibility problem that most projects quietly ignore:

  • You wrote the world and the agent. Nothing stops you from tuning reality until your agent wins, and nothing proves to a reader that you did not.
  • You tuned against the same data you report. A number that has been optimised against is a measure of fit, not of performance.
  • An agent that wins might have won for the wrong reason. If a language-model agent beats a rules agent, was it the model, or was it the better decision arithmetic around it?

Each of those has a specific structural answer in this project, and they drove almost every design decision in it.
